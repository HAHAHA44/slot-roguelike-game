# 生肖携带年度结算规则，而非给同共鸣碎片加成

M1 结束时，`ZodiacDefinition` 只有 `id / display_name / order` 三个字段，当年生肖与奖励格只
喂给 UI 和日志，**对结算零影响**——"12 格生肖盘"这条硬约束当时纯粹是美术。我们决定让
**每个生肖各携带一条在它轮值那一年生效的结算规则**（如"基础分 ≤3 的碎片额外 +4"、
"邻接联动半径 +1"），12 条互不相同，12 年一轮。

## Considered Options

最直觉的做法是"当年生肖对应共鸣的碎片吃加成"，但它算不通：玩家一共只有命盘 12 + 行囊 6 =
18 张碎片，凑不齐 12 个生肖的对口牌，于是九成年份行囊里没有可换的东西——而行囊每年值得打开
正是它存在的理由。把生肖映射到碎片类别（fortune / bond / virtue）能解决覆盖问题，
但 12 个生肖里会有三四个是同一件事，12 年周期退化成 3 年周期。

年度规则两个问题都不犯：规则年年不同，玩家永远有理由调阵，且不需要"凑对口生肖"。

## Consequences

- `SettlementService.settle()` 要接受当年规则，`CascadeContext` 要能承载它——
  这是整套改动里最重的接口变更之一。
- 生肖轮值是确定性的，玩家看得到明年是什么年，于是产生"为明年做准备"的前瞻。
  这是 build 感的主要来源，也是行囊调阵的动机。
- 本命年不走年度规则，改用"同生肖共鸣 ×N"的极端加成，作为 12 年一次的高潮。
